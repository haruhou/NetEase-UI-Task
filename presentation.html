让 AI 先筛选，业务员只处理高意向买家

这是对「网易外贸通 · 拓客Agent - 潜客会话」页面的重新设计。功能全部保留，我主要做了三件事：让 Agent 的状态一眼能看清，让高意向买家更容易被找到，缩短从发现到回复的操作路径。视觉上刻意做减法，让页面里需要被注意的地方少一些。

人机分工流程 接管路径最短化 每个区域只留一个重点色 状态看板可折叠 显示 AI 判断依据
设计目标 更快找到高意向买家，降低接管的操作成本
核心角色 国内出海卖家 / 外贸业务员 / 营销主管
重构模块 Agent 状态头部、会话列表、对话区、买家档案抽屉
配套产物 可交互的 React 原型（单文件 dashboard.html）
Chapter 01 · Problem Framing

原页面的问题：用户得自己在一堆信息里找重点

拓客Agent 会同时跟进很多买家，业务员真正需要处理的只是其中少数高意向的人。原页面没有帮用户把这些人挑出来，只能靠肉眼逐个排查，漏看一个就可能丢掉一个订单。

我看到的三个主要问题
问题 1 · 看不出 Agent 在做什么
  • 状态不明： 头部只有任务名称，看不出 Agent 现在是在准备、在触达，还是遇到了问题。
  • 数据割裂： 触达、回复、高意向几个数字各自独立，看不出转化关系，也就没法判断这个任务做得好不好。
问题 2 · 会话列表太杂
  • 标签太多： 高意向、新会话、在线等标签颜色各不相同，都在抢注意力，结果哪个都不突出。
  • 没有理由： 列表只告诉用户这是高意向，没说为什么。想确认就得点进去读完聊天记录。
问题 3 · 接管路径太长（Fitts's Law）
  • 来回移动： 接管按钮在右上角，点完之后还要把视线和鼠标移到页面底部的输入框才能打字。
  • 入口重复： 页面里有 3 处接管入口，位置分散，用户不确定该点哪一个。
Chapter 02 · Collaborative Framework

我的思路：Agent 负责广泛触达，人只在关键时刻介入

我没有把 AI 和业务员当成两套各自独立的功能，而是先想清楚分工：什么时候 AI 自己处理，什么时候该提醒人来接手。整个流程分成三步。

Stage 1 · AI 自动跟进
Agent 批量触达
Agent 负责首轮开场、初步筛选和翻译，可以跨时区持续进行。这个阶段业务员不用介入，只需要在头部看进度。
Stage 2 · 触发提醒
出现高意向信号
买家索要产品目录或报价、主动留下 WhatsApp、说出具体采购量时，会话会被标为待接管，并排到列表前面。
Stage 3 · 人工接管
业务员接手
点击接管后，输入框立即可用，Agent 暂停自动回复并留下买家画像。处理完可以直接跳到下一个待接管的买家。
1
头部「待接管」：把待办集中在一处 Trigger
头部直接显示有多少买家在等人接手（如「4 个高意向待接管」）。点击「去处理」，列表会筛选到这些买家，并默认选中第一个。
2
列表里写明 AI 的判断理由 Identify
选中的会话用深炭灰突出，卡片上直接写出判断依据，如「询问报价 · 要求产品目录 · 连续回复 3 次」。业务员先看理由，再决定要不要点进去读全文。
3
接管按钮放在输入框旁边 Action
接管按钮直接放在底部输入区。点击后光标自动进入输入框，鼠标不用再移动。发送完成后，可以直接进入下一个待接管的买家。
Chapter 03 · UX & Interaction Redesign

具体怎么改：状态头部、会话列表、对话区

模块 1 · Agent 状态头部
让用户随时知道 Agent 在做什么
  • 状态可见： 「Agent 正在跟进」配黄绿色标签和轻微的呼吸动效，表示它正在工作。
  • 漏斗可点： 「已触达 / 有效回复 / 高意向」三个指标可以点击，点击后列表按对应条件筛选。
  • 准备阶段： 新建任务时显示三步进度（筛选 → 生成话术 → 自动触达）。
  • 可以折叠： 头部能收成一条细的状态栏，给会话列表留出更多纵向空间。
模块 2 · 会话列表与买家档案
帮用户更快判断先看谁
  • 买家头像： 每个买家有独立的头像，方便快速认人。
  • 组合筛选： 支持按行业、国家、时间段和 7 个快捷标签组合筛选。
  • 买家档案抽屉： 点击头像或档案按钮，从侧边滑出，内容包括采购需求、公司背景、AI 画像和背调信息，不用离开当前会话。
  • 可调宽度： 列表和对话区之间可以拖动调整宽度，适应不同尺寸的屏幕。
模块 3 · 对话区与翻译
小语种消息也能直接看懂
外贸买家会使用各种语言和行业缩写。对话区提供中文译文开关，每条消息都标明来自 AI Agent、业务员还是买家，也支持直接预览产品图片。
Chapter 04 · Design Discipline & Iteration

视觉上做减法：让重点只剩一两处

我最初的版本用了不少黑色块和黄绿色高亮，做完发现每个元素都很显眼，反而没有重点。后来我把颜色收回来，只留给真正需要被看到的地方。

视觉上的前后对比
迭代前：处处都在强调
  • 顶部导航、高意向标签、会话卡片都用了纯黑色块。
  • 黄绿色同时出现在头部整张卡片、每个标签和未读点上。
  • 每个组件都想被看见，视线没有落点。
迭代后：每个区域最多一个重点
  • 深炭灰只给选中项： 会话列表里只有当前选中的会话用深炭灰（#2e2e2c），作为唯一的视觉锚点。
  • 导航和标签弱化： 顶部导航和侧栏的选中态改为浅灰底深色字，标签用浅色描边。
  • 黄绿色只给行动： 只用在「去处理」按钮和状态小圆点上，引导用户走到关键操作。
  • 背景分层： 用浅暖灰背景（#efeeea）加白色卡片和轻阴影，去掉不必要的描边。
深炭灰 (#2e2e2c)
只用于：当前选中的会话卡、主新建按钮、业务员已发送的消息气泡。
黄绿强调色 (#dcea4e)
只用于：「去处理」按钮、AI 运行指示、需要人工处理的状态点。
暖灰与白 (#efeeea / #fff)
侧栏、头部、列表、对话四块独立的圆角卡片，靠间距区分层次。
Chapter 05 · Impact & Deliverables

总结与可体验的 Demo

以下是设计层面的判断，目前还没有用户测试数据。如果有机会继续做，我会优先验证两点：接管路径是否真的更短，以及 AI 的判断理由是否能让业务员更快决定先回谁。

路径更短
接管
接管按钮和输入框放在一起，从发现高意向买家到开始回复，少了一次跨区域的鼠标移动。
判断更快
识别
列表直接写出 AI 的判断理由，业务员可以先看理由再决定要不要点进去，不必通读英文聊天记录。
功能完整
范围
原题要求的功能都保留了（多任务切换、续期、筛选、搜索、找客工具、买家详情），没有删减。
